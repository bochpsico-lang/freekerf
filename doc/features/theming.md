# Theming and density

Themes and densities come from the `fk-` design tokens of `freekerf/design`
(`ui/tokens/fk-tokens.css`, generated by `cargo xtask sync-tokens` at the commit in
`ui/tokens/design.lock`). Components use semantic and density tokens only, never
primitives, so switching a theme touches no component.

| Setting (`settings.toml` `[ui]`) | Values | Effect (attributes on `<html>`) |
| --- | --- | --- |
| `theme` | `dark` (default), `light` | `data-theme` |
| `high_contrast` | `false`, `true` | `data-contrast="high"` (pure black, white 2 px borders, lighter amber) |
| `density` | `auto` (default), `compact`, `comfortable` | `data-density`; `auto` follows the last pointer: touch → comfortable (44 px targets), mouse or pen → compact |
| `units` | `mm`, `in` | rulers, DRO and status bar |

- The settings change through `settings.set` (Display and input dialog, status bar
  units button); the UI never reads the TOML file.
- Automatic density switches only on a new press, never during a drag
  (`design/interaction.md` §1). The status bar shows the input kind and "auto".
- The canvas reads its colours from the same tokens (`ui/web/src/canvas/theme.ts`)
  and reads them again when the theme changes.
- Layer colours do not change between themes (they belong to the file).
- `prefers-reduced-motion` stops the running stripes and the alarm blinking.

Tests: `freekerf-settings::ui_section_is_optional_and_settable`, `src/App.test.ts`
(theme and contrast through `settings.set`), `src/state/environment.test.ts`
(density resolution).
